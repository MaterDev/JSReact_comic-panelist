I spent the morning refactoring my Comic Panel App, which got me thinking about the tradeoffs of AI-assisted coding approaches.

Agentic AI tools are incredible for rapid development. You can build more features in days than would take weeks with traditional coding. But there's a catch that becomes increasingly apparent as projects grow...

Technical debt piles up FAST. 

A big goal in my  #Agentic workflow is maintaining a clean architecture that both human and AI can understand. Here's what works for me:


#TIPS

👉🏾 My workflow starts with thoughtful planning. I write clear, properly sized tasks with specific acceptance criteria and have AI create a plan of action before diving in. To optimize token usage, I offload planning work to browser-based tools like #Claude (which can import GitHub repos directly), saving #Windsurf's allocation for actual code changes. This preparation phase is crucial for keeping the project on track.

👉🏾 During development, I use commits strategically to track progress and make reverting changes easier. With Windsurf, I can isolate Cascade changes and apply them only when they're working correctly. I address lint errors and warnings immediately before they multiply, and I reorganize code aggressively to reduce technical debt. Maintaining a clean architecture that both human and AI can understand prevents the project from becoming unwieldy.

👉🏾 I share code between components and explicitly specify in prompts that existing code should be used when possible, since AI's limited context means it might forget what's already been done between sessions. I review code regularly (even when it's just me reviewing the AI's work) and maintain a logging system beyond git that tracks changes and updates. These logs help me understand the context of changes and can be referenced in future prompts to help the AI understand the project's evolution.

These practices aren't new, but they become even MORE critical when working with AI. Things can quickly get out of hand!
